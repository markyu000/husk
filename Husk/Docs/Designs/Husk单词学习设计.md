## 一、设计哲学

**学习与复习分离。** 学习时充分（多阶段、多维度），复习时高效（自测 + 拼写验证）。

**错误推迟而非循环。** 学习过程中答错某一步，整个词排到学习队列末尾过一会儿重来，而不是当场反复重做。这天然形成"间隔效应"。

**主观自测 + 客观测试。** 自测告诉算法用户的信心，测试验证用户的真实掌握度。

**FSRS 只在复习时介入。** 学习过程的对错不喂给 FSRS，只有自测结果（初始化时）和复习结果（更新时）影响调度。

**响应速度即信号。** 自测环节中"多快做出判断"本身携带信息——瞬间反应出的"认识"和思考几秒后才想起来，代表两种不同置信度的记忆状态，因此需要用不同路径处理。

## 二、核心概念

### 2.1 三大阶段

每个新词的学习最多包含三个阶段，按顺序进行（具体是否全部经过取决于自测结果，见第四章）：

| 阶段 | 内容 | 测试形式 |
|------|------|---------|
| **释义阶段** | 单词的中文/英文含义（测试内容受设置影响，见 4.4.0） | 选择题 |
| **听音阶段** | 单词的发音 | 选择题 + 自测 |
| **拼写阶段** | 单词的字母组成（看着释义拼写） | 键盘输入 + 选择 |

### 2.2 自测机制

Husk 中有两类自测，逻辑不同，注意区分：

#### A. 限时自测（学前自测 Step 0 / 复习自测 5.2）

初始展示三个选项：

| 按钮 | 含义 |
|------|------|
| 认识 | 立即确信认识（3 秒内点击有效） |
| 模糊 | 有印象但不确定 |
| 不认识 | 完全没印象 |

**限时规则**：卡片出现后计时 3 秒。若用户在 3 秒内点击"认识"，记为**认识（即时）**——高置信度的瞬间识别。若 3 秒内未点击，"认识"按钮文案自动替换为**"想到了"**——用户仍可点击，但代表"经过几秒回忆才想起来"，是较低置信度的延迟识别。"模糊""不认识"两个按钮全程可点，不受计时影响。

所以一次限时自测最终会落入四种结果之一：**认识（即时）／想到了（延迟）／模糊／不认识**，但用户界面上任意时刻只显示三个按钮。

学习流程与复习流程中，这四种结果各自触发不同路径，详见第四、五章。

#### B. 听音自测（学习流程 Step 6）

仅两个选项，无计时机制：

| 按钮 | 含义 |
|------|------|
| 认识 | 能通过发音辨认出单词，并能想起中英文含义 |
| 不认识 | 想不起来 |

不再提供"模糊""想想"选项——听音阶段是对释义阶段已建立记忆的二次确认，只需要一个清晰的是/否判断。

### 3.2 按钮逻辑

- **复习按钮**：进入复习流程，逐个过到期的词。
- **学习按钮**：进入学习流程，先学新词，再重学复习失败的词。

复习池为空时复习按钮置灰。学习池和待重学都为空时学习按钮置灰。

复习与学习都只在当前这一个 Unit 内进行，不会与其他 Unit（哪怕同为单词型）的卡片混排。

## 四、学习流程

### 4.1 总览

```
进入学习
  ↓
取队列首词
  ↓
学前自测（Step 0，限时自测）
  ↓
  ├─ 认识（即时，3秒内点击）
  │     → 进入检查页（4.3），可直接点"全部掌握"（无需勾选任何项）
  │     → 点"全部掌握" → 直接进复习池 → FSRS 初始化（Easy）
  │     → 勾选未掌握项 → 走对应的释义阶段/拼写阶段（不含听音阶段）
  │
  ├─ 想到了（3秒后点击）
  │     → 进入检查页（4.3），**必须至少勾选一项未掌握**，不能直接"全部掌握"
  │     → 走对应的释义阶段/拼写阶段（不含听音阶段）
  │
  ├─ 模糊
  │     → 仅执行 Step2（中→英）+ Step5（听音→选义）
  │     → 直接进入拼写阶段（Step7，逻辑同"不认识"）
  │     → FSRS 初始化（Good）
  │
  └─ 不认识
        → 完整流程：释义阶段（Step1-3，受设置影响）
                   → 听音阶段（Step4 条件跳过 / Step5 / Step6）
                   → 拼写阶段（Step7，必要时 Step7a）
        → FSRS 初始化（Again）
  ↓
任何步骤答错
  → 整个词排到队列末尾，记录当前阶段与当前学习路径
  → 下次从该阶段第一步开始（沿用同一条路径，"模糊"简化路径重来时仍是简化路径）
  ↓
全部步骤通过
  → 进入 FSRS 调度（按 Step 0 结果对应的 Rating 初始化，学习过程中的对错不改变该 Rating）
  → 取下一个词
```

### 4.3 检查页（"认识"与"想到了"共用）

#### 显示

```
┌─────────────────────────────┐
│  abandon  🔊 /əˈbændən/      │
│                             │
│  请确认你都掌握了：           │
│  （勾选不会的，点击重点学习）  │
│                             │
│  📖 中文含义                 │
│  ☐ v. 放弃；遗弃            │
│  ☐ v. 抛弃（家人朋友）       │
│  ☐ n. 放纵；无拘束          │
│                             │
│  ✏️ 拼写                    │
│  ☐ a-b-a-n-d-o-n           │
│                             │
│  ─────────────────         │
│                             │
│  [ 全部掌握 ✓ ]              │
│  （"想到了"入口本按钮禁用，   │
│  勾选任意项后变为"重点学习"）  │
│                             │
└─────────────────────────────┘
```

> 若释义测试模式（4.4.0）设为"替换释义"，则"📖 中文含义"栏替换为"🇬🇧 英文释义"；若设为"关闭"，则不受影响（本页始终只展示当前生效的释义类型，不再单独列出英文释义行）。

#### 逻辑

检查页由 Step0 自测的两个"高置信度"分支共用（认识/想到了），但两者对"全部掌握"按钮的可用性不同：

| 自测来源 | "全部掌握"按钮 | 不勾选任何项时 |
|---------|---------------|---------------|
| 认识（即时） | 可用 | 允许直接点击通过 |
| 想到了 | **禁用** | 必须至少勾选一项未掌握才能继续 |

- **认识**入口：不勾选任何项，点"全部掌握" → 进入 FSRS 调度（Easy，初始 stability = w[3] ≈ 15.69 天）
- **想到了**入口：按钮禁用，用户必须勾选至少一项未掌握，才能点击"重点学习"继续（不存在"想到了但全部掌握"这一条路径——如果用户确实全都掌握，理应在 3 秒内就点"认识"，"想到了"这个较低置信度的判断本身就意味着至少有一部分需要巩固）
- 两种入口下，勾选未掌握项后走向相同：
  - 勾了释义项 → 走释义阶段（Step1-3，受 4.4.0 设置影响）
  - 勾了拼写项 → 走拼写阶段（Step7）
  - 同时勾两类 → 按顺序走（释义阶段 → 拼写阶段），**不经过听音阶段**
  - 完成后仍按 Easy 初始化 FSRS（自测入口是"认识"或"想到了"，与是否做了重点学习无关）
- 重点学习中如果答错，走引擎层通用的失败详情页（见 5.5 / 附录A），依然按"错则排到队列末尾"的规则处理，且沿用同一条重点学习路径（不会额外插入听音阶段）。详情页展示范围见下方"失败详情页展示范围"说明。

#### 失败详情页展示范围（学习流程通用规则）

学习流程中除 Step7 外的任何步骤答错，都会先展示失败详情页（完整卡片信息+高亮答错部分）。展示的内容范围取决于这张卡当前是否处于"重点学习"（即检查页勾选过部分内容）：

- 若这张卡是通过检查页勾选"部分未掌握"进入当前学习路径的 → 详情页只展示被勾选（收窄后）的学习内容
- 若这张卡未经过检查页收窄（如"模糊""不认识"两条路径，或检查页选择了"全部掌握"之外的默认全量情形不适用于本条，因其已直接学完）→ 详情页展示完整内容

这与三、架构设计文档"失败详情页"机制一致：详情页内容来自 `card.fullDetailContent()`，具体到单词型，是否收窄取决于 `learningContentDefinitionIDs`/`learningContentEnglishDefinitionIDs` 是否被设置（见代码文档 `learningDefinitions()`/`learningEnglishDefinitions()`）。

### 4.4 释义阶段（Step 1-3）

#### 4.4.0 设置：释义测试模式

在设置中可选择 Step3 的行为，三选一：

| 模式 | 说明 | 实际测试内容 |
|------|------|-------------|
| **关闭** | 纯中文释义，不测英文释义 | 仅 Step1（英→中）+ Step2（中→英） |
| **替换释义** | 用英文释义替换中文释义作为测试内容 | Step1（英→英文释义选择）+ Step2（英文释义→选词），不再有独立 Step3 |
| **单独步骤（默认）** | 保留原设计 | Step1（英→中）+ Step2（中→英）+ Step3（英英→中） |

三种模式下 Step1/Step2 是否出现、出现几题都不变，变化的只是"测中文还是测英文释义"以及"是否额外增加 Step3"。卡片本身仍然同时存储中文释义与英文释义，设置只影响测试内容，不影响卡片正面展示的信息。

#### Step 1：英→中（默认模式；"替换释义"模式下为 英→英文释义）

```
│                             │
```

## 五、复习流程（v2，按代码文档 husk-word-card-code.md 四同步）

> 本节取代此前版本。核心变化：复习自测选"认识"后会弹一个确认页（与学习流程检查页同构，但可以不勾选任何项直接通过）；模糊路径不再有"快速唤醒题"；拼写测试答错（含模糊分支）统一转入完整重学，不再有独立的"拼写补救"选择题步骤；"不认识"直接进重学；任何答错（及复习自测的"模糊"）都会先展示失败详情页（完整信息+高亮答错部分），这是引擎层的通用能力，不只发生在复习流程。

### 5.1 总览

```

  │     → 全部掌握 → 进入拼写测试，拼对 FSRS Easy，正常计算间隔
  │     → 勾选了不会的项 → 弹失败详情页（按 5.2.1 勾选范围）→ 转入完整重学（见 5.4）
```

  - 若来源是"想到了" → FSRS 内部记为 Hard，但 dueDate 强制覆盖为明天
  - 若来源是"模糊" → FSRS 更新为 Easy，按算法正常计算下次间隔
- 拼错 → 弹失败详情页 → 转入完整重学（5.4），**不再有独立的拼写补救选择题步骤**

### 5.4 完整重学

"不认识"（自测阶段直接触发）与"拼写测试答错"（无论来源是认识/想到了/模糊）**共用同一条重学路径**：

1. 该词状态改为"学习中"
2. 走学习流程"模糊"那条简化路径——只做 Step2（中→英）+ Step5（听音→选义），然后进入拼写阶段（Step7），**不是**从释义阶段 Step1 起的完整流程
3. FSRS 按 **Again** 初始化——本轮复习是失败的，不论走到重学前选的是"模糊"还是"不认识"

这条重学路径复用学习流程已经定义好的 Step2/Step5/Step7/Step7a（见四），不是另一套独立内容。

### 5.5 失败详情页（复习流程中的表现）

复习流程里任何一次答错（复习自测选模糊、拼写测试答错、重学过程中 Step2/Step5/Step7 答错）都会先展示一个详情页——完整的单词信息（释义+拼写+例句等），用高亮的方式标出这次具体错在哪，用户确认后才继续走后续流程（排队/转重学）。这不是复习流程专属的设计，而是引擎层对所有失败场景的通用处理（学习流程同样适用，见四）。

## 六、队列管理

### 6.1 队列（v2，按代码文档同步）

| 队列 | 内容 | 来源 |
|------|------|------|
| 新词队列 | 今日要学的新词 | 用户添加 / 词书导入 |
| 复习队列 | 今日 FSRS 到期的词 | FSRS 调度 |
| 完整重学队列 | 复习中"不认识"或拼写测试答错的词 | 复习流程（5.4） |

> 此前版本设计中的"待重学队列"（拼写补救失败后的轻量重试）已随拼写补救环节一起废弃。复习失败统一走"完整重学队列"，走学习流程"模糊"路径的简化子图（Step2+Step5+Step7），不再有单独的轻量补救分支。

以上队列均是**某一个具体单词型 Unit 的私有状态**，不同 Unit（哪怕都是单词型）之间的队列互不相通。

### 6.2 复习按钮行为

```
点击复习
  ↓
执行复习队列（FIFO）
  ↓
按 5.1 的三种分支分别处理
  ↓
拼写测试答错、复习自测"不认识"的词 → 转入完整重学队列
"模糊"的词 → 排回复习队列末尾，轮到时进拼写测试
其余通过的词更新 FSRS（含"想到了"的次日强制调度）
  ↓
复习队列清空，结束
```

### 6.3 学习按钮行为

```
点击学习
  ↓
合并队列：新词队列 + 完整重学队列（新词在前）
  ↓
执行 FIFO：
  - 取队首
  - 若为全新词：学前自测（Step 0）决定路径
  - 若为完整重学队列词：跳过 Step 0，直接从 Step2 起（模糊路径的简化子图）
  - 学完 → 进入 FSRS（完整重学统一按 Again）→ 本轮已学完计数 +1
  - 达到本轮学习目标（见 6.3.1）→ 结束本轮学习会话，返回 Unit 主界面
  - 答错 → 弹失败详情页 → 排到队尾，记录当前阶段与路径
  ↓
队列清空（本轮目标之前已耗尽全部待学词），结束
```

### 6.3.1 单次学习目标

**背景**：一个 Unit 里待学的新词/待重学词可能很多，一次性学完容易疲劳。引入"单次学习目标"，让每次进入学习界面只学一批，学完这批就自然收尾，用户可以选择返回主界面或立即开始下一轮。

**规则**：

- 目标以"本轮已学完的卡片数量"计数，**只统计真正学完（进入 FSRS 调度）的卡片**，学习过程中途答错、排回队尾不计入，也不计负数
- 目标数量是 **Unit 级别**的设置，每个 Unit 可以有自己的目标值；若 Unit 未单独设置，使用**全局默认值**（在 App 设置里配置，如默认 10）
- 达到目标后，**当前正在进行的词不会被打断**——如果打断的是一个已经进了检查页/释义/拼写阶段的词，允许其走完，学完那一刻计数达标后再结束会话（不会在半路把一张卡强行悬挂）
- 会话结束后展示一个简短总结（学了几个词、还剩多少待学/待重学），并提供"返回主界面"与"再来一轮"两个入口
- "再来一轮"会重新走一次同样的学习按钮逻辑（6.3），沿用同一批未学完的队列继续往下取，不重新洗牌顺序
- 若 Unit 内待学词总数本身少于目标值，正常提前耗尽队列结束，不强行凑够目标数量

**界面示意（学习完成汇总页，替代/追加在 4.7 单卡完成页之后，当计数达标时展示）**：

```
│                             │

│   剩余待重学：1 个            │
```

- 昨天的**新词队列**未学完的保留到今天

- 复习中标记"想到了"的词，dueDate 已被强制设为明天，会自然出现在明天的复习队列中

## 七、FSRS 算法集成

### 7.1 算法选择

使用 **FSRS-5**（Free Spaced Repetition Scheduler v5），社区目前公认最优的开源 SRS 算法，跨类型共用同一套引擎（见 husk-architecture-code.md 第二节）。

### 7.2 默认参数

沿用 FSRS-5 论文默认 19 个权重，最大间隔 100 年。**目标记忆保留率（desired retention）不再是全局固定的 90%**，改为每个 Unit 创建时通过滑块单独设置（80%–97%，默认 90%），创建后不可修改——具体的产品理由和滑块交互见架构设计文档九。本节及本文档其余出现的"stability ≈ N 天"数值，均只由自测 Rating 决定（w[3] 等初始权重与 retention 无关），不受某个 Unit 具体设置的 retention 影响，可以放心跨 Unit 复用同一套参考数值。

### 7.2.1 "学完不再复习"的判定

一张卡不会被永久标记为"已掌握"后从复习队列里摘除——FSRS 仍然对它保持追踪，due date 到了依然会正常出现。但当它的 stability 已经把下次复习间隔自然拉长到一年（365 天）以后，产品上把它归类为"学完"，用于展示（比如 Unit 首页统计"已学完：N 个"），不影响调度本身。

由于 365 天的间隔标准要换算成具体的 stability 阈值，而这个换算跟 Unit 的 `desiredRetention` 相关（retention 越高，撑出同样长的间隔需要的 stability 越高），所以这个阈值是随 Unit 变化的，不是全局统一的一个天数。具体公式和字段见架构代码文档四（`Unit.masteredStabilityThreshold`）。

### 7.3 自测到 Rating 的映射（学前自测，Step 0）

```
认识即时   → Rating.easy   → 初始 stability ≈ 15.69 天，走检查页（4.3，可直接"全部掌握"通过）
想到了     → Rating.easy   → 初始 stability ≈ 15.69 天，走检查页（4.3，必须至少勾选一项未掌握），
                              无论"认识"还是"想到了"入口，最终都按 Easy 初始化
模糊       → Rating.good   → 初始 stability ≈ 3.17 天，走 Step2+Step5+拼写阶段
不认识     → Rating.again  → 初始 stability ≈ 0.40 天，走完整流程
```

> "认识"与"想到了"最终都按 Easy 初始化，区别只在于检查页"全部掌握"按钮是否可用（前者可直接通过、后者强制至少勾一项），不影响 FSRS 数值——这与"学习过程的对错不喂给 FSRS"的设计哲学保持一致。

### 7.4 FSRS 介入时机（v2）

| 时机 | 操作 |
|------|------|
| 新词学完 | 初始化 FSRS 状态，用 Step 0 自测结果对应的 Rating（见 7.3） |
| 复习：认识（即时）+ 拼写对 | FSRS.schedule(rating: .easy)，按算法正常计算间隔 |
| 复习：想到了 + 拼写对 | FSRS 内部记为 .hard，但 dueDate 强制覆盖为明天 |
| 复习：模糊 + 拼写对 | FSRS.schedule(rating: .easy)，按算法正常计算间隔 |
| 复习：拼写测试答错（不论来源） | 转入完整重学，不在此处更新 FSRS |
| 复习：不认识 | 不在此处更新 FSRS，直接转入完整重学 |
| 完整重学学完 | FSRS.schedule(rating: .again)，统一按 Again 处理 |
| 学习中答错 / 完整重学中答错 | **不更新 FSRS**（FSRS 不知道这事） |

> "想到了"分支的次日强制调度是在标准 FSRS 计算结果之上的覆盖（override），不修改算法本身，便于未来关闭该覆盖时无缝回退到标准 FSRS 行为。

## 附录 A：错误处理规则速查

> 以下所有"排到队列末尾"/"转入完整重学"之前，均先展示失败详情页（完整信息+高亮答错部分），这是引擎层通用能力，下表不再逐行重复标注。展示范围规则见 4.3 节"失败详情页展示范围"：若该卡当前学习内容被检查页收窄过，只展示收窄后的部分，否则展示完整内容。

| 场景 | 规则 |
|------|------|
| 学前自测 3 秒内选"认识" | 进入检查页（4.3），可直接"全部掌握"通过，FSRS 初始化 Easy；若勾选未掌握项则走对应阶段 |
| 学前自测 3 秒后选"想到了" | 进入检查页（4.3），必须至少勾选一项未掌握 |
| 学前自测选"模糊" | 仅执行 Step2 + Step5，随后进拼写阶段（Step7），FSRS 初始化 Good |
| 学前自测选"不认识" | 走完整流程（释义→听音→拼写），FSRS 初始化 Again |
| 检查页（认识入口）不勾选，点"全部掌握" | 直接进复习池，FSRS 初始化 Easy |
| 检查页（想到了入口）勾选未掌握项（必选） | 走对应释义阶段/拼写阶段（不含听音阶段），FSRS 仍按 Easy 初始化 |
| 释义阶段任一步答错 | 词排到队列末尾，下次从释义阶段开始（同一路径） |
| Step4 跳过条件 | 释义阶段 Step1 首次即答对 → 跳过；否则必须执行 |
| 听音阶段（含 Step6 选"不认识"）任一步答错 | 词排到队列末尾，下次从听音阶段开始（Step4-6 视条件重新判断/全部重做） |
| 拼写 Step7 错 | 进入 7a |
| 拼写 7a 错 | 词排到队列末尾，下次从拼写阶段（Step7）开始 |
| 复习自测选"认识" | 进入复习确认页（5.2.1），可直接"全部掌握"通过继续拼写测试；勾选任意未掌握项则直接转入完整重学 |
| 复习自测选"想到了" | 直接进入拼写测试（不弹确认页），拼对则 dueDate 强制设为明天；拼错转入完整重学 |
| 复习自测选"模糊" | 弹失败详情页，排到复习队列末尾，轮到时进入拼写测试（与"认识全部掌握"共用同一步） |
| 复习自测选"不认识" | 不进入拼写测试，直接转入完整重学，FSRS 初始化 Again |
| 复习拼写测试答错（任意来源） | 转入完整重学，不再有独立的拼写补救选择题步骤 |
| 完整重学（不认识 / 拼写答错 / 认识确认页勾选未掌握） | 走学习流程"模糊"路径的简化子图（Step2+Step5+Step7），学完后 FSRS 统一 Again |

## 附录 B：术语表

- **FSRS**：Free Spaced Repetition Scheduler，开源间隔重复算法
- **Stability（稳定性）**：FSRS 中表示记忆强度的核心变量，单位为天
- **Difficulty（难度）**：FSRS 中表示该卡片对用户的难度，1-10
- **Retrievability（可提取性）**：当前时刻能成功回忆该卡片的概率
- **Rating**：FSRS 的 4 档评分（Again/Hard/Good/Easy）
- **限时自测**：学前自测 / 复习自测使用的三按钮+计时机制，"认识"在 3 秒后变为"想到了"
- **听音自测**：Step 6 使用的二选一自测（认识/不认识），无计时机制
- **阶段**：学习流程的三大分组（释义/听音/拼写）
- **路径（learningPath）**：一个词在学习流程中具体经过哪些阶段（完整/模糊简化/检查页重点学习）
- **步骤**：阶段内的具体测试（如 Step 1, Step 2）
- **Unit**：一整套独立的记忆系统（如"雅思单词本"），本文档所有流程均发生在某一个具体的单词型 Unit 内部
- **Card**：具体的记忆条目，本文档语境下即一张 `WordCard`
- **失败详情页**：任一 Step 判定失败时自动展示的完整卡片信息页（高亮答错部分），引擎层通用能力，学习/复习流程共用，见五、5.5
- **完整重学**：复习流程中"不认识"或拼写测试答错后走的统一路径——学习流程"模糊"路径的简化子图（Step2+Step5+Step7），FSRS 统一按 Again 处理，见五、5.4
